# Wort 世界地形规划器（离线版 v2）

这是一个**抽象世界布局数据编辑器**，不是体素地形生成器。完整代码只有 `index.html` 一个文件，双击后通过现代浏览器离线运行，无需 Unity、服务器或安装任何依赖。地图 PNG 只是总览图；真正用于后续体素生成器的内容是**分层 JSON**。

## 主要操作

| 快捷键 | 功能 | 操作 |
| --- | --- | --- |
| `B` | Biome 区域 | 选人类区 / 湿地 / 森林 / 针叶林 / 山地 / Moorland / 海岸，按住拖动涂色；右键拖动擦除；设置笔刷直径（米） |
| `M` | Chunk 标记 | 选随机 / 固定 / 过渡 / 不可通行，**单击 Chunk 切换，再点同一格取消**；拖动可连续标记 |
| `P` | 关键地点 | 点击放置带名称、类别、圆形 / 方形和可调半径的图钉 |
| `R` / `C` | 河流 / 峡谷 | 按住拖动绘制带宽度的中心线 |
| `L` | 初步路线 / 最终道路 | 选择阶段，依次点击添加折点；`Enter` 或双击完成；可设置单向通行与道路类型 |
| `T` | 台地 / 盆地 | 依次点击 ≥3 个顶点，`Enter` 或双击封闭多边形；设置相对高差（米） |
| `V` | 选择 | 点击选中对象并编辑；拖动图钉或路线 / 高差区的亮色顶点；`Delete` 删除 |
| `H` | 平移 | 拖动移动视角；滚轮缩放（任何模式下空格 / 中键拖动可临时平移） |

`Ctrl+Z` 撤销、`Ctrl+Shift+Z` / `Ctrl+Y` 重做、`Esc` 放弃当前未完成的折线 / 多边形。左侧“图层可见性”可**分别隐藏初步路线和最终道路**、Biome、河流、峡谷所在层、高差区域、地点、Chunk 网格和标记；隐藏不删除数据。

右侧可以修改**世界长宽（4–48 Chunk）**、步行速度、现实分钟制的一天时长，并查看直线穿越时间。每 Chunk 固定为 `64×64m`。缩小地图可能裁剪越界数据，工具会要求确认。可用按钮标记最外圈不可通行及第二圈过渡。

## 重要设计边界

- **Biome 是二维硬边界分类**：笔刷与 Chunk 网格独立，绘制时无描边、无噪声、无羽化。每个位置只属于一种 Biome 或“未涂色”；重叠区域最后涂的类别生效。
- 导出 JSON 时额外计算每 `4m×4m` 一个单元的**离散分类遮罩**，以有损的空间采样分辨率表达原始硬边界；原始笔触向量数据同时保留，适合后续重新采样。4m 只用于宏观规划数据导出，不是体素精度。
- 体素生成器后续可在抽象规划基础上叠加起伏、噪声、Biome 过渡等。**规划器本身完全不生成、不融合、不模拟**这些内容。
- 台地 / 盆地多边形记录**相对高度规划值**，不直接代表最终体素高度图，也不自动解决坡道、通行关系或地形碰撞。道路与单向方向只是输入约束，通行验证由后续实现负责。
- 工具不修改 Unity 现有代码、GDD 或 `Docs/DevLog.md`。

## 保存与导出

- 自动保存到浏览器 `localStorage`，可能因清理浏览器数据而丢失；请定期手动导出 JSON。
- **导出 JSON**：包含全部可编辑的分层矢量数据，以及可直接读取的 Biome 分类栅格遮罩。它是核心交付物。
- **导入 JSON**：替换当前规划（支持 v2 和原 v1 布局），可撤销。v1 以 Chunk 为单位的 Biome 会迁移为同尺寸的二维硬边界矩形数据；v1 道路导入为“最终道路”。
- **导出 PNG**：仅作视觉总览；图层是否可见会影响展示，但视图缩放和平移不影响完整世界导出的范围，**不能拿 PNG 反推原始规划数据**。

### JSON v2 示例（省略了部分数组）

```json
{
  "schema": "wort-world-layout",
  "version": 2,
  "chunkMeters": 64,
  "world": { "columns": 16, "rows": 16 },
  "planning": { "speedMps": 4, "dayMinutes": 24 },
  "layers": {
    "biomes": {
      "model": "hard-edge-categorical-mask",
      "marks": [
        { "id": "brush1", "shape": "stroke", "biome": "wetland", "width": 64,
          "points": [[100, 120], [160, 130]] },
        { "id": "erase1", "shape": "stroke", "biome": null, "width": 12,
          "points": [[120, 140]] }
      ],
      "raster": {
        "cellMeters": 4, "columns": 256, "rows": 256,
        "encoding": "rle-row-major",
        "codebook": ["unpainted", "human", "wetland", "forest", "conifer", "mountain", "moorland", "coast"],
        "runs": [[0, 6000], [2, 22]]
      }
    },
    "chunkZones": [{ "x": 4, "y": 5, "zone": "random" }],
    "places": [{ "id": "home1", "name": "住所", "category": "home", "shape": "circle", "radius": 40, "x": 450, "y": 600 }],
    "hydrography": {
      "rivers": [{ "id": "r1", "kind": "river", "width": 12, "points": [[100, 40], [120, 100]] }],
      "canyons": []
    },
    "elevationZones": [{ "id": "z1", "name": "北部台地", "kind": "plateau", "offsetMeters": 6,
      "points": [[120, 100], [200, 100], [200, 190], [120, 190]] }],
    "routes": {
      "draft": [{ "id": "d1", "name": "初步路线", "stage": "draft", "type": "trail", "oneWay": false,
        "points": [[200, 200], [250, 240]] }],
      "final": []
    }
  }
}
```

**注意**：以上 `raster.runs` 是说明格式的**截断示例**，不是可直接导入的完整遮罩。实际工具导出时会写入完整的 RLE。

**坐标约定**：原点为左上角；X 向右、Y 向下，地点、线条、宽度和高度分区顶点都使用世界米制坐标；Chunk 的 `(x,y)` 为零起始索引。`chunkZones` 与 Biome 不互相覆盖。`raster.runs` 按行优先平铺，每项是 `[类别代码, 连续单元数]`，全部连续单元数之和等于 `columns × rows`。代码 `0` = 未涂色；`1..7` 按 `codebook` 的顺序对应七种 Biome。没有渐变值。**导出的 `marks` 是可编辑的原始笔画，`raster` 是其在 4m 单元中心的结果快照**；导入时以 `marks` 为准，重新导出时重算 `raster`。

### 后续生成器如何使用

建议读取 `layers` 作为独立上游数据：关键地点与河流、峡谷给出宏观约束；Biome 确定大致生态区域；台地、盆地约束相对地势；参考初步路线后再沿地形实施最终道路；Chunk 标记用于划分后续手工 / 随机处理范围。最终如何合并这些约束由体素生成器确定，此工具**不偷偷编码生成规则**。
