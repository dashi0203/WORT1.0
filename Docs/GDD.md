## 1. 项目定位

Wort 是一款以真实生态、开放世界探索、生存冒险和炼金术为核心的 3D RPG，写实、低魔。【已定】

- 参考：《Stoneshard》的生存探索体验，融合《星露谷物语》的长期经营、NPC 生态和世界生活感。
- 主角不是传统英雄，而是以炼金术为核心专业的冒险者。
- 不再采用工厂自动化（Factorio-like）方向。【已定】

整体目标是建立一个能长期运转、有内在逻辑的世界，而不是堆积系统。玩家应该能够：

1. 因为好奇心而探索世界。
2. 因为观察和判断而发现隐藏资源。
3. 因为风险和资源限制而进行策略选择。
4. 通过炼金术和生产建立稳定的经济来源。
5. 通过交易和积累逐渐改善生存条件。
6. 在一个有四季、生态、NPC 和长期变化的世界中生活。

## 2. 核心玩法循环

实时制。【已定】核心循环如下图，每一轮都把玩家推向更危险的区域。【已定】

*核心玩法循环 · 8 个环节*（原文为图，此处改写为列表）：

1. 探索世界
2. 发现资源与环境线索
3. 采集与狩猎
4. 战斗和冒险
5. 加工与炼金（主角的核心专业）
6. 交易获利
7. 改善生存条件
8. 前往更危险的区域

第 8 步之后回到第 1 步，进入下一轮。

- **探索**：不是单纯找资源点，而是观察环境、识别线索，利用工具与知识发现隐藏内容。
- **战斗**：敌人威胁较高，冒险需要考虑装备、补给、环境和风险，不靠数值碾压。
- **炼金**：主角始终以炼金为核心专业，不发展成全能工匠。制作受时间、设备、环境影响，强调真实的生产过程。【已定】
- **生活节奏**：玩家可以长期采集、生产、积累商品，形成稳定的日常生产与收入来源，但不经营零售店。【已定】

## 3. 视觉与相机

真实 3D 世界，用统一的 45° 错切投影呈现为 top-down 画面。【已定】旧项目的 2D 像素美术不沿用。【已定】

- **美术风格**：PSX 风格低模 3D，不依赖低分辨率相机或像素画。【暂定】
- **相机**：以 topdowntemp 的 WortShearCamera 为起点。正交相机垂直朝下，投影矩阵加垂直错切（shear = 1，orthoSize 9.5）。地面保持纯俯视，高度 h 在屏幕上上移 h。【暂定】
- **压扁规则**：地形和大部分物件不压扁。只有人物，以及个别和人放在一起会产生比例歧义的物件，使用 VisualYScale 压扁。地形是固定的参照尺度。【已定】
- **其他可沿用的效果**：VisualCameraTilt（模型朝相机前倾 12°）、VerticalTiltShift（按世界高度做移轴模糊）。【待讨论】

参考画面：1m 台阶朝南的一面在屏幕上约一格高，人物约一格宽、一格半高；朝北的面不可见。

## 4. 世界结构

有边界、地图足够大的开放世界，由 64m × 64m 的 chunk 拼成。【已定】

| 项目 | 设定 | 状态 |
| --- | --- | --- |
| chunk 尺寸 | 水平 64m × 64m | 【已定】 |
| 世界规模 | 16×16 到 32×32 个 chunk，小于 2km 见方 | 【暂定】 |
| 地表高度 | 设计目标不超过 32m，通常更矮 | 【已定】 |
| 高度上限 | 硬上限 56m（预留，正常不会用到），只可能出现在北边的高原；雪山只是入口，不占大地图高度 | 【已定】 |
| 地下深度 | 最多 8m（0 层以下），只放小洞穴、地窖、矿脉；山体里从台地侧面挖进去的洞穴在 0 层以上，不受此限 | 【已定】 |
| chunk 纵向组织 | 一个 chunk 是一整根柱子，竖直范围 −8 到 +56（共 64m），内部再切小块做网格 | 【暂定】技术细节 |
| 存档 | 生成结果由数据重建，存档只记差量（玩家修改、资源状态） | 【暂定】 |

- chunk 只是存储和加载的网格，不是生态单位；同一个 chunk 里可以有多种地形和生态。【已定】
- 区域用世界坐标上的区域 ID 图表示，与 chunk 无关；区域温度偏移也按它取值。【暂定】
- 地图方位：北边是高原，雪山入口也在北边；东边和南边是海岸，有港口大城市。【已定】
- 0 层为海平面。低于 0 层不等于水：海水只填和海连通的低处，其余可以是干的盆地或谷底。【已定】
- 地形与中国有一点相似（阶梯状下降），但不重要；文化不采用中国体系。【已定】
- Biome 清单见第 6.1 节；Biome 之间的边界用渐变【已定】。

长线副本（雪山、巨木沼泽、深渊）和程序化地牢是特殊关卡，单独进入，不在连续大地图中；长线副本在大地图上只是一个入口预制件，没有对应地形。【已定】详见第 12 节。

## 5. 地形与体素

体素是地形与空间结构的基础，尺寸暂定 1m（与初版 2D 的格子一致），实际游玩效果待原型验证。【暂定】

**体素形状集**（每格 = 材质 + 形状）：

| 形状 | 数量 | 说明 |
| --- | --- | --- |
| 整格 | 1 |  |
| 斜坡 | 4 | 每个朝向一种，用于地表过渡 |
| 直半墙 | 4 | 厚度减半（0.5m），高度仍是整格，贴在一条边上 |
| L 形半墙拐角 | 4 | 用于墙体转弯 |
| T 形 / 十字半墙 | — | 墙体交汇时可能需要，原型阶段不做 |

- 半墙指厚度减半，不是高度减半。【已定】
- 地表不用平滑网格；地表过渡靠斜坡。【已定】
- 地表相对平坦，但不是大部分平坦；起伏的处理方式仍是一个讨论方向。【待讨论】

**可破坏性**【已定】：地表整体不能挖；只有特定的东西能挖或破坏（石板、矿点）。可破坏物建议做成摆在体素网格上的物件。【暂定】

**跳跃与攀爬**【已定】

- 1m 可以跳上去；2m 不可攀爬，只能往下跳。
- 坠落伤害：往下跳 1–3 层无伤，4 层受伤，5 层重伤，6 层有概率摔死，7 层以上必死。【已定】具体伤害数值与摔死概率【暂定】
- 跳跃距离：水平约 2–3.2 格，高度能跳上 1 层多一点（够不到 2 层）。生成时要绝对避免主角从外部或内部隔着几格跳上墙、山体等不该上去的地方。【已定】
- 特殊可攀爬地形（粗糙岩壁、藤蔓、碎石坡）只出现在悬崖**正面**（朝相机的一面），因为侧面攀爬在 top-down 里难以计算。

**悬崖**：insect 式的高垂直悬崖是重要的区域划分手段。【已定】

**悬崖背面规则**【已定】：南高北低、崖面朝北的悬崖，其台地顶面在屏幕上会盖住崖脚北侧约“崖高”宽的一条地面。这一条区域：

- 尽可能少生成资源。
- 不生成可爬的坡，也不生成能跳上去的 1m 台阶。
- 人物走进去时，中间的体素虚化（见第 7 节）。

## 6. 世界制作流程

大世界主体是生成后由策划手工修改、再烘焙的数据；运行时只生成随机 chunk 和地牢。【已定】

**半手工流程**【已定】

1. 策划提供大世界布局：关键地点、区域划分与层级、出入口、道路（见第 6.4 节）。
2. 生成器按布局生成 Biome 图、地形和关键地貌（借鉴 insect 的群系混合、悬崖、坡道、水面做法），并检查连通性。
3. 策划在其中逐个 chunk 手工修改，集中在部分区域，以地表为主。
4. 村庄里的细节装饰、道路等由策划手动摆放。
5. 烘焙保存，之后不再被生成器覆盖。

**随机区域**【已定】

森林深处等有怪物的区域由一组随机 chunk 构成迷你迷宫，玩家睡觉后整块重新生成。

| 规则 | 设定 |
| --- | --- |
| 组成 | 由策划指定哪些 chunk 是随机的，形状任意（如 L 形 3 个 chunk），chunk 之间边相连 |
| 候选出入口 | 每个边相邻的固定 chunk 提供一个，位置由策划标在共享边上（L 形 3 个 chunk 周围有 7 个） |
| 开放出入口 | 每次刷新开放 1–3 个，其余封死；封口放在随机一侧，固定 chunk 永不改动 |
| 地形连贯 | 必须和周围固定 chunk 在基础体素上大致连贯：外圈接缝带沿用邻居边缘高度，内部平滑插值；只随机地表附近几米，地下用烘焙数据 |
| 迷宫 | 靠高低差和无法逾越的植物分隔；难度偏难，考验物资 |
| 内容槽 | 内容按房间和深度摆放（宝箱、怪物、任务刷新点），数量按面积算；细则见《随机区域与关卡生成》 https://claude.ai/artifact/FLi4oaxFPRfPHC75a3KqcF |
| 穿越 | 可以从任一开放出入口进出，随时可以从就近出口离开 |
| 物品与资源 | 区域内的东西不会自己刷新，只随区域整体刷新；进入时提示丢失的东西拿不回来 |

**刷新时机**

- 玩家回家睡觉，或在野外距离随机区域超过 1 个 chunk 的地方睡觉，都会触发刷新，出入口也会随之改变。
- 玩家在随机区域内，或距离区域 1 个 chunk 以内睡觉，不刷新。
- 野外睡觉要消耗睡袋，第二天精力上限会缩短。

**单行路**：不做运行时防困死机制，由生成结构保证——单行路段要么通往出口，要么有别的办法出去。校验时一次性通道按单行处理。

**通道类型**（第一版，细节待设计）

| 类型 | 可重复 | 方向 | 代价 |
| --- | --- | --- | --- |
| 平路 / 斜坡 | 是 | 双向 | 无 |
| 荆棘 | 是 | 双向 | 用刀或镰刀砍掉，或硬穿（按衣服判断受伤） |
| 蚊虫区 | 是 | 双向 | 驱虫药水或火把 |
| 可攀爬岩壁 | 是 | 往上要攀爬 | 消耗精力；只在悬崖正面 |
| 2 格及以上悬崖 | 是 | 只能往下跳 | 构成单行路；4 层起有坠落伤害（见第 5 节） |
| 一次性藤蔓 | 否 | 往上 | 用完就断 |
| 一次性荷叶 | 否 | 双向 | 踩坏就没了；踩空落水 → 潮湿 |
| 高悬崖、深水 | — | 不可通过 | — |

## 6.1 Biome

地表生态只用 Biome 一层分类；地形起伏和地物（湖泊、池塘、河流、悬崖带）都写在各 Biome 自己的生成规则里。【已定】

| Biome | 位置 / 说明 | 主要树种 | 少量树种 |
| --- | --- | --- | --- |
| 人类区 | 底子是缓丘低地草原，再放村庄、农田、道路；可有湖泊、河流 | 杨树（路边成排）、柳树（河边） | 橡树、枫树 |
| 混交林 | 人类区周围；可有随机区域 | 橡树、山毛榉、枫树、白桦 | 杨树、松树 |
| 寒带针叶林 | 偏北、靠近山地；可有随机区域 | 松树、云杉 | 白桦 |
| 沼泽 |  | 柳树、小杨树 | 白桦 |
| 山地 | 含原高原；洞穴比其他 Biome 多 | 松树、云杉（越高越稀） | 白桦 |
| 荒原（moorland） |  | 几乎无树 | 零星矮松、白桦 |
| 海岸 | 东边和南边，有港口大城市 | 松树 | 杨树 |

- Biome 清单【已定】；树种分布【暂定】。不设丘陵；雪山暂不考虑。【已定】
- 森林以后可能有更多种类，1.0 先做混交林和寒带针叶林两种。【已定】
- 初版树木素材：Birch 白桦、Maple 枫树、Toplar 杨树（3 种变体）、treeswap 小杨树（沼泽）、beech 山毛榉、oak 橡树、pine 松树、spruce 云杉、willow 柳树；均有树桩状态。
- 森林和山地都可能生成有落差的河流；生成器标记落差点，瀑布由策划手动摆放。【已定】
- 各 Biome 的高低起伏规则见第 6.3 节。

## 6.2 Chunk 制作管线与环境场

每个 chunk 按“地形 → 环境 → 植物”三层顺序制作，每层可单独生成和手改；修改某一层时，它的下游必须是空的。【已定】

| 层 | 内容 | 来源 |
| --- | --- | --- |
| ① 地形 | 体素（材质 + 形状） | 生成 → 手改 |
| ② 环境 | 湿度、地表分区、土壤、扰动等二维场，1m 一格 | 由 ① 推导 + 随机生成 → 手改 |
| ③ 植物 | 植物实例列表 + 草药候选点 | 由 ② 生成 → 手改 |

**规则**【已定】

- 要改上游，先清空下游（工具弹窗确认）。改环境必须先清空植物层；改地形会清空环境层和植物层。
- 不做植物锁定、冲突标记、手绘覆盖层叠加；每层存的就是最终结果。
- 跨 chunk：改动某个 chunk 的地形时，若相邻 chunk 已生成环境或植物，工具只提示可能受影响，不自动清空。
- 推荐按片区批量推进：先定整片地形，再统一生成环境，最后统一生成植物。

**环境场**【暂定】

| 场 | 类型 | 来源 |
| --- | --- | --- |
| 地表高度、高度层 | 推导，不存盘 | 体素 |
| 坡位（平地 / 崖顶边 / 崖脚 / 斜坡） | 推导，不存盘 | 高度差 |
| 朝向（阳面 / 阴面） | 推导，不存盘 | 高度差 |
| 水体、水深分层、水距 | 推导，不存盘 | 水体素 |
| 湿度 | 生成后可手改 | 水体扩散 + 地表分区修正 + 噪声 |
| 地表分区 | 生成后可手改 | 斑块噪声 + Biome 分区表 + 湿度、坡位条件 |
| 土壤（肥力、酸性） | 生成后可手改 | 地表分区查表 + 噪声 |
| 扰动度 | 生成后可手改 | 低频斑块：林窗、倒木区、旧伐区 |

- 地表分区按格子所在的 Biome 取各自的分区表（如混交林：林下落叶层、林窗草本、蕨类、湿苔阴地）。
- 光照不属于环境层，在植物层内部根据树冠计算。
- 不加风 / 暴露度场。【已定】

**湿度场的计算**【暂定】

1. 计算一个 chunk 时向四周多读 16m 邻居水体，保证跨 chunk 连续。
2. 线性时间的最近水体距离变换（Burst），同时记录最近水面高度。
3. 只在编辑器里使用，运行时不保留。

```latex
\text{湿度} = \text{区域基础} + \text{水体影响} \times f(\text{水距}, \text{扩散半径}) \times g(\text{高于水面的高度}) + \text{地表分区修正} + \text{噪声}
```

**植物层**【暂定】

1. 乔木锚点 → 计算光照场 → 灌木 → 草本 → 地被（可做成地表贴图或贴片）。
2. 候选位置用世界坐标的确定性蓝噪声点，团簇中心也按世界坐标，跨 chunk 不出缝。
3. 草药不在植物层摆实例，而是烘焙每种草药的候选生成点（位置 + 适宜度）；运行时资源区域只从候选点里挑位置。

**植物生态位表**【暂定】：每种植物一行，加新植物只加一行，生成器不改。

| 字段 | 说明 |
| --- | --- |
| 植物 ID、层级 | 乔木 / 灌木 / 草本 / 地被 |
| Biome、地表分区 | 可出现的列表或权重 |
| 湿度、土壤、扰动、光照 | 每项给最适区间 + 容忍区间 |
| 坡位、朝向、水距 | 偏好与限制 |
| 成组方式 | 组大小、组内间距、组间留空 |
| 排斥规则 | 避开某些植物或地物 |

适宜度 = 各项匹配程度的乘积。

## 6.3 地形生成

先由世界布局（第 6.4 节）定出 Biome 区域图，再按权重混合各 Biome 的起伏参数，最后在世界坐标上用噪声生成地形。【已定】

**连续性原则**

- 所有噪声和场都是世界坐标的函数，chunk 只是最后切块的位置。【已定】
- Biome 边界用渐变：Biome 区域图边界模糊成权重图，过渡带约 32–64m。【已定】
- 混合参数，不混合高度：台地覆盖率、高度等参数按权重混合后，再用同一套噪声生成并量化到整数层，避免“半截悬崖”。【暂定】
- 生成时如果旁边有已手修的 chunk，把它们的边缘高度当作固定约束。【暂定】

**两个阶段**【暂定】

| 阶段 | 范围 | 内容 |
| --- | --- | --- |
| A. 区域级二维 | 整片区域一起算（如 8×8 个 chunk） | 高度、台地、水系、坡道、连通性修复 |
| B. chunk 级三维 | 每个 chunk 单独算 | 体素化：地表、悬崖面、斜坡、地下岩层 |

阶段 A 步骤：

1. 读取输入：世界布局（区域形状与层级、关键地点、出入口、道路）及由它给出的 Biome 区域图、可选的河流主干。
2. Biome 权重图：边界模糊成渐变带。
3. 宏观高度：平滑后作为底。
4. 微起伏：世界坐标噪声，幅度按 Biome 权重混合。
5. 区域内部台地：低频块状噪声（加扰动）按混合后的覆盖率取阈值；再用更高频、更稀疏的噪声在台地上叠出高台和孤峰。
6. 水系：河流从高往低走并下切；按 Biome 生成池塘、浅洼；标记落差点供手摆瀑布。
7. 量化与清理：取整到层，去掉碎块、补小洞、修锯齿。
8. 坡道与连通性：在笔直崖边放 2–3 格宽坡道；小块封闭区填平，大块开坡道（沿用 insect 思路）。布局指定的区域边界只在出入口开口，生成器不自动修改，只做检查。

**地形元素**（单位：层 = 1m）

| 元素 | 高差 | 面积 | 说明 |
| --- | --- | --- | --- |
| 微起伏 | 0–1 层 | — | 默认是台阶（可直接跳上）；少量用斜坡让起伏更自然，整体比例要小【已定】 |
| 矮台地 | 1–2 层 | 小到中 | 开放区可有，可叠一次；2 层形成短的单行边；沼泽自身起伏加矮台地总高不超过 3m【已定】 |
| 主力台地 | +3–4 层 | 中到大 | 所有 Biome 都有；边缘清晰、连接口少；人类区的由策划手动擦除【已定】 |
| 高台 | 每级 +3–4 层 | 小，单边约 8–16m | 地标、瞭望点；叠在主力台地上逐级上升，北部高原叠到 16–24m；基本没有坡道 |
| 孤峰 | 6–10 层 | 很小，约 4–8m | 只有山地有【已定】 |
| 大悬崖带 | 7 层以上 | 线状 | 高原边缘（可直接落到森林）、海岸；只在布局指定的位置出现，跳下必死 |
| 沟谷 | 向下 1–2 层 | 线状 | 沿溪流下切 |

- 台地越高，面积越小【已定】；高台必须落在已有台地上或附近，高度逐级上升。
- 台地顶部最窄不小于 8m；两块台地之间的通道不小于 4m；每段笔直崖边至少 2–3 格。
- 悬崖背面规则按高度放宽：被挡住的一条宽度约等于崖高。

**各 Biome 起伏参数**【暂定，第一版起点，原型中调整】

| Biome | 宏观高度 | 微起伏 | 台地覆盖率 | 高度上限 | 叠层 | 每块台地的坡道 | 特点 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 人类区 | 低 | 0–1，大而缓 | 10–15% | 2 层 | 无 | 2–3 | 大台地 20–60m；村庄区域手动擦平 |
| 混交林 | 低–中 | 0–1 | 15–20% | 4 层 | 偶尔 | 1–2 | 溪谷下切形成支沟；林中岩丘 |
| 寒带针叶林 | 中 | 0–2 | 20–25% | 5 层 | 最多 2 级 | 1 | 更崎岖，巨石多 |
| 沼泽 | 最低 | 0–1 | ≤5% | 3 层 | 无 | 1 | 水面在 −1 层；孤立岩岛 |
| 山地 | 高（+8 到 +24） | 0–2 | 40% 以上 | 6 层以上 | 2–4 级 | 0–1 | 外缘大悬崖带；崖面洞口；孤峰 |
| 荒原 | 中 | 0–2，长缓坡 | 10–15% | 5 层 | 无 | 2 | 线状断崖；岩冢 |
| 海岸 | 降到海平面 | 0–1 | 内陆 ≤5% | 5 层 | 无 | 1 | 30–50% 海岸线是海崖；海蚀柱 |

- 宏观高度（哪里低、哪里高、阶梯在哪）正式版由世界布局的区域层级给出；第一个 8×8 实验由程序自由发挥。【已定】

**工具链需求**【暂定】：需要一个 Unity 编辑器内的体素 chunk 编辑工具（笔刷、体素形状、物件摆放、资源区域 spline），以及一种便于入仓、体积可控的 chunk 数据格式。

## 6.4 世界布局

世界先定布局，再定 Biome 和地形；道路、策划画的台地 / 盆地和峡谷决定主干连通关系，生成器不能破坏；离开道路以后，生成器随机产生的台地 / 盆地可以自由形成窄道、死胡同和绕路；体素生成后由策划手改。【已定】完整规格见仓库 `Docs/WorldGen.md`。

**布局顺序**【已定】

1. 关键地点：城市、村庄、住所、长线副本入口、野外建筑、自然奇观。地点可以小于一个 chunk，也可以跨越多个 chunk。
2. 地理区域：每个地点所在区域的类型、范围、层级与出入口；区域可以嵌套。
3. 道路：在已有地理结构上连接各地点，含小径、山路；马车网络是道路网的子集。
4. 固定 chunk：碰到地点、道路、区域边界、出入口、桥和隧道的 chunk 一律固定。
5. 随机区域：在剩余的完整 chunk 里安排。
6. 整体校验：有向连通、步行距离。

**原则**【已定】

- 大地图的布局和道路由策划设计并确认；布局是一次性设计。
- 分割手段：台地、峡谷、盆地、高原落差。两个地点直线近但希望路程远时，用分割逼人绕路。
- 相邻不等于可以通行；允许双向、单向和不可直通，入口与出口可以不同。
- 道路在平面上重叠处标明平交或立交；立交上下不互通（桥、天然拱、隧道）。桥的护栏由策划手动加。
- 随机区域不能是固定区域之间的必经之路：固定世界不经过随机区域也能自己连通。
- 形状尽可能有机：大于 5×5m 的区域、台地、盆地、地点地面一律是不规则形、椭圆或圆形；5×5m 及以下（坡道口、台阶口、门洞）可以规则。

**区域类型**【已定】

| 类型 | 层级 | 边界 | 内部 |
| --- | --- | --- | --- |
| 开放区（森林、沼泽、人类区等） | 0 左右 | 自己的边界不成崖 | 自然起伏、1–2 层矮台地、少量 3–4 层台地 |
| 台地区 | 周围 +3–4 | 一圈崖，只在出入口有坡道 | 平整或轻微起伏 |
| 盆地 | 周围 −2 及以下 | 一圈崖；跳进去，原路出不来 | 另有出口 |
| 峡谷 | 两侧高、谷底低 | 两侧长崖 | 沿狭长通道移动；谷底有自己的出入口 |
| 高原 | 每级 +3–4，叠到 16–24m | 外缘可 7 层以上直接落到森林 | 多级台地 |

## 7. 空间呈现

室内、洞穴、地下空间统一打 layer；地下和室内用高度裁切呈现。【已定】

**Layer 的用途**

| 用途 | 说明 | 状态 |
| --- | --- | --- |
| 淋雨判断 | 在室内 layer 里的东西（如晾晒架）不会淋雨 | 【已定】 |
| 专属灯光 | 为了让玩家看清室内而加的假灯，只影响室内 layer（URP Rendering Layer Mask） | 【已定】 |
| 高度裁切的触发 | 玩家进入室内或地下 layer 时启用裁切 | 【暂定】 |

- 房屋的 layer 在生成房屋时一起带上；程序化洞穴和地牢由生成器自动带上。【已定】

**高度裁切**【暂定】

- 规则：裁切高度 = 玩家所在地面 + k 格（k 约 2–3），露天时不裁切。
- 实现：shader 中按世界 Y 做 clip，裁切变化时不重建网格；剖切面显示深色实心截面。
- 进出时是平滑过渡还是瞬间切换、是否加“视野圆”：在原型中调。【待讨论】

**遮挡虚化**【已定】：人物被遮挡时，它与相机之间的体素地形虚化。与高度裁切同时存在时是否冲突，待原型验证。

## 8. 环境与气候

环境分为生成时烘焙的静态环境场和运行时的气候；世界有昼夜和四季循环。【已定】

**静态环境场**（生成时产生，策划修改后烘焙）：群系、土壤类型、肥力、离水距离、海拔、基础气温。【暂定】

- **湿度**：不作为每个体素或 tile 的信息。【已定】作为生成输入场，并以粗分辨率（每 8–16m 或每 chunk 一个值）保留。【暂定】

**气温**【已定】：以气温为主，作用于整个世界和部分生态区域。

```latex
\text{气温} = \text{季节基础值} + \text{天气偏移} + \text{区域偏移}
```

- 季节基础值和天气偏移沿用初版 TempBaseSeason / TempWeatherOffset 表的思路。
- 区域偏移是新增的一层：有的区域低 1–2 度。
- 区域温度同时影响腐烂速度、积雪和作物。

**天气**【已定】：沿用初版的天气种类及其表现。雨天会让室外正在晾晒的草药直接腐烂。

**季节表现**【已定】

| 现象 | 规则 |
| --- | --- |
| 积雪 | 会盖住地面资源，可用鹰眼视觉找到；物体上也会有积雪，所以在雪地里会凸出来 |
| 积雪减速 | 只在温度低、积雪更厚的区域减速 |
| 枟萎 | 只是植被（灌木、草地）的外观变化；单株草药没有枟萎阶段 |
| 河流结冰 | 可以走上去，可以凿冰钓鱼 |

## 9. 资源区域与刷新

资源以真实的 3D 实体存在于世界中，由资源区域统一管理刷新；低魔世界观下野外资源本身就少。【已定】

**资源区域**【已定】

- 形式：手工放置的 spline 区域，或热力图。区域承载其中所有可生成资源物件的刷新判定（树木、池塘等）。
- 每个区域有基础产出速率，有的区域天然高一些；土壤肥沃的地方长得快一些。
- 刷新量随季节变化。
- 区域可以重叠，重叠处资源种类取并集；每个物件只属于生成它的区域，只扣该区域的存量。【暂定】
- 不做过度采集惩罚。【已定】
- 资源刷新与睡觉无关。【已定】

```latex
\text{存量}_{新} = \min(\text{上限},\ \text{存量} + \text{基础速率} \times \text{肥力} \times \text{季节系数} \times \text{经过天数})
```

**离线补算**【已定】：远处区域不实时模拟，只记录上次更新时间；chunk 加载时按经过天数和季节一次性算出当前状态。

**资源物件的三类**【暂定】

| 类型 | 例子 | 刷新方式 |
| --- | --- | --- |
| 出现 / 消失型 | 草药、蘑菇、地上的石块 | 区域在空位上生成新物件，以幼体出现再长大 |
| 常驻 + 状态型 | 树、灌木、果树 | 物件一直在，状态循环（结果 → 摘取 → 再结果） |
| 抽象库存型 | 池塘里的鱼、矿脉 | 只有一个存量数字，采集时从中扣除 |

**隐藏资源**【已定】

- 石块可以翻动，石板可以破坏，地下可能藏有矿物或特殊内容。
- 石头下的东西也归区域管，在区域刷新时就决定好，不在翻开时才随机。
- 鹰眼视觉：购买图鉴后开启，用来搜寻不显眼的资源。只高亮已解锁的物种。【暂定】

**地表与地下的线索**【已定】：线索必须是画面上看得见的物件，如指示植物、岩石颜色或纹理、地面形状（塌陷的坑）。不做冷风这类看不清的线索。生成时可以先放地下的矿脉和洞穴，再据此决定地表线索。【暂定】

## 10. 植物、动物与种植

植物在世界里真实地长出来，动物不细致模拟，玩家只能在自家 chunk 种植。【已定】

**植物**

- 3D 物件真实地长出来。【已定】
- 新资源以幼体出现再逐渐长大；离线补算时一并算出生长阶段。【暂定】
- 单株草药没有枟萎阶段；只有灌木一类有枟萎阶段。【已定】

**动物**【已定】

- 不细致模拟；绑定在 chunk 里，生成在地面上。
- 玩家离开一个 chunk 的距离（约 64m）就消失。
- 生成表按区域取（一个 chunk 里可能有多个区域），季节通过改变生成表来体现。

**种植**【已定】

| 规则 | 设定 |
| --- | --- |
| 可种植范围 | 只有玩家的家所在的 chunk |
| 种子 | 稀缺资源；种出来的草药产种子的概率极低，限制玩家种田致富 |
| 品质 | 由田块所在的环境决定（与“品质由采集环境决定”一致） |
| 土壤 | 玩家不能改良土壤 |
| 施肥 | 1.0 不做；预留能影响作物的词条，效果持续一次收获 |
| 浇水 | 需要浇水，每天只判断一次（参考星露谷物语） |
| 温度 | 区域温度偏移影响作物 |

- 每日结算时间：玩家可以熬夜，所以可能是 0 点或次日 6 点。建议 6 点，与起床时间对齐。【待讨论】
- 下雨是否算浇水。【待讨论】

## 11. 物品系统

物品系统以初版策划表的多项数值和 tag 为核心；新增品质和新鲜度两项实例数据。【已定】

**沿用的初版表结构**（来源：FactorioLike 的 ItemConfig.xlsx 与 9 草药 Demo 配置）

| 表 | 关键字段 |
| --- | --- |
| ItemDef | ID、类型、Tags、占格 W×H（网格背包）、堆叠上限、是否会腐烂、使用动作与效果组、燃烧时长、买卖价 |
| PerishableDef | 保质期、腐烂后替换成的物品 |
| ContainerDef | 格子尺寸、允许的 Tag、腐烂倍率（箱子 0.8、地面 1.5） |
| RecipeDef / StationDef | 配方、设备、耗时、燃料 |
| EffectGroup | 使用效果（疲劳、中毒、寒冷、疾病等数值变化） |

- 加工状态做成独立物品：鲜品 → 干燥 → 研磨粉 → 药液 → 药剂。【暂定】
- 用 Tag 驱动“哪个设备收什么”：Dryable、Grindable、Boilable、Mixable 等。【暂定】
- 初版 HerbPool（地形类型 × 天气 → 加权草药池）由第 9 节的资源区域取代。【暂定】

**实例数据**【已定】

- 材料的属性和品质由采集时的环境决定。
- 物品身上至少带品质和新鲜度。是否再记录产地、采集季节【待讨论】。
- 堆叠：品质不同不能叠；新鲜度不同叠在一起时取最差的。

**腐烂**【已定】

- 草药有新鲜度，会腐烂，必须晒干或制成不会腐烂的东西。草药保质期暂定 48h。
- 不受环境湿度影响；地窖温度低，东西烂得慢。
- 雨天会让室外正在晾晒的草药直接腐烂；室内 layer 里不受影响。

```latex
\text{腐烂速度} = \text{物品基础速度} \times \text{容器倍率} \times \text{所在位置的温度系数}
```

## 12. 地牢与长线副本

地牢和长线副本都是单独进入的独立空间。【已定】

**地牢**【已定】

- 程序化生成的体素地牢，独立空间，会刷新；一般主角离开后地牢就消失。
- 地牢地图是商品，在城镇购买后地牢才会生成。
- 地牢地图也能在地牢中获得，但一般是高难地牢。
- 野外随机地牢：遇到概率非常小，定期刷新一定数量，分散在各个 chunk 里；玩家运气好才能碰到。
- 地牢入口做得看起来容易塌陷，所以会消失。
- 生成器自动给地牢带上地下 layer。

**长线副本**【已定】：共三处——雪山、巨木沼泽、深渊。每处在大地图上只是一个固定的入口预制件，没有对应地形；进入后独立加载。雪山入口在北边。

- 巨木沼泽、深渊入口的具体位置。【待讨论】
- 长线副本的内容、规模与呈现方式（如雪山内部的高差与相机）。【待讨论】

- 地牢的内容、规模、主题、与地图商品属性的对应。【待讨论】

## 13. 经济与交易

主角不经营零售店，携带商品前往专业买家处出售；不做无限刷新和无限套利。【已定】本节尚未展开讨论。

- 专业买家体系：如铁匠收购金属矿石、熔剂；不同买家按自己的行业需求收购不同商品。【已定】
- 商品价值与用途、品质、买家需求和市场供应有关。【已定】
- 适度的跨地区贸易，但不能靠简单的低买高卖迅速致富。【暂定】
- 偶尔出现的大型商队提供特殊交易机会。【暂定】
- 买家需求饱和：同一买家收同类货价格下降，随时间恢复。【待讨论】
- 炼金是消费端，在实现上与资源端的环境解耦；两者通过“材料品质由采集环境决定”连接。【已定】炼金系统细节尚未讨论。
