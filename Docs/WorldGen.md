# Wort 世界生成规格

> 草稿 v0.1 · 2026-11-10 · 负责人确认前为草稿
> 本文件定义大世界的布局（layout）与地形生成规则，是生成核心 `Assets/Wort/Scripts/Generation/` 的直接依据。
> 设计层面以 GDD（https://claude.ai/artifact/S6CtD759fRjLrJdhjF5inT）为准；两者冲突时以 GDD 为准，并在第 12 节列出待同步项。
> 本文件直接在仓库里编辑，不是快照。来源：2026-11-10 与负责人的讨论，以及已并入的 `codexsug/WorldLayoutRules.md`（Draft 0.2）。

标记沿用 GDD：【已定】已经明确确认；【暂定】当前倾向，可调；【待讨论】未决定。

## 1. 总原则

**关键地点决定世界布局，地理结构决定空间关系，道路连接这些地点，固定 chunk 保存世界骨架，随机区域最后填充。**【已定】

- layout 先于 Biome 和地形。【已定】
- 拓扑（哪里能走、往哪个方向走、哪里必须绕路）只由 layout 决定；生成器只填细节，不制造、不修改区域之间的连通关系。【已定】
- 大地图的 layout 和道路由负责人设计并确认；Claude 可以出草案，但只有确认过的版本进入生成器。【已定】
- 分割手段：台地、峡谷、盆地、高原落差。两个地点直线近但希望路程远时，用分割逼人绕路。【已定】
- 全图 layout 是一次性设计；8×8 技术验证用的 layout 只验证管线，不沿用到 16×16。【已定】

## 2. 世界规格

| 项目 | 设定 | 状态 |
| --- | --- | --- |
| chunk | 水平 64m × 64m | 【已定】（GDD） |
| 世界规模 | 16×16 个 chunk（GDD 为 16×16 到 32×32） | 【待讨论】 |
| 体素 | 1 层 = 1m | 【暂定】（GDD） |
| 海平面 | 0 层 | 【已定】 |
| 竖直范围 | −8 到 +56，一根 chunk 柱子 64×64×64 | 【已定】 |
| 地下 | 地面 0 以下最多 8 层；只放小洞穴、地窖、矿脉、隐藏资源 | 【已定】 |
| 地上设计目标 | 不超过 32m；生成参数按 32m 调 | 【已定】 |
| 地上硬上限 | 56m，只作数据格式与总高度钳制的余量 | 【已定】 |
| 长线副本 | 雪山、巨木沼泽、深渊在大地图上只是入口预制件，没有地形 | 【已定】（GDD rev 34） |

- 山体里的洞穴是从台地侧面往里挖，位于 0 层以上，不受地下 8 层的限制。
- 低于 0 层不等于水：0 层以下可以是干的盆地或谷底（见第 7 节）。【已定】

## 3. 高差与通行

跳跃规则沿用 GDD：1m 能跳上，2m 及以上爬不上、只能往下跳。坠落伤害为新增。

| 高差 | 往上 | 往下跳 | 作用 | 状态 |
| --- | --- | --- | --- | --- |
| 1 层 | 能跳上 | 无伤 | 开放区的自然起伏 | 【已定】 |
| 2–3 层 | 不能 | 无伤 | 单行边；矮台地 | 【已定】 |
| 4 层 | 不能 | 受伤 | 主力台地边缘；跳下要付代价 | 【已定】 |
| 5 层 | 不能 | 重伤 | | 【已定】 |
| 6 层 | 不能 | 有概率摔死 | | 【已定】 |
| 7 层以上 | 不能 | 必死 | 硬分割：高原边缘、深峡谷 | 【已定】 |
| 坡道 / 台阶 | 双向 | 双向 | 规则的连接口 | 【已定】 |
| 桥 / 隧道 | — | — | 上下交叉但不互通 | 【已定】 |

- 伤害的具体数值、概率摔死的概率【暂定】，后续写进 GDD 生存部分。
- 7 层以上的崖边要让人看得出来（崖边石块、植被断带、崖面颜色变深等），具体做法在原型中定。【待讨论】

**不能被噪声破坏的边**【已定】

- 区域边界、出入口以外的崖边上，任何噪声、碎石、杂物都不能补出 1 层的台阶，否则单行边会变成双向。
- 高差大于 4 层的崖，崖脚可以加噪声体素（碎石堆、凸岩）让它不生硬；碎石顶部必须比崖顶至少低 2 层。碎石本身可以爬。

## 4. 生成管线

```
layout（结构图 + 地点 + 出入口 + 道路 + 约束）
  → Biome 图（由 layout 给出，边界渐变）
  → 地形：区域层级 → 地点印章 → 区域内部噪声 → 水系 → 量化
  → 三维结构印章：桥、拱、隧道
  → 检查：有向连通、步行距离、出入口与 layout 一致
  → chunk 体素化（阶段 B，沿用 GDD 6.3）
```

- 结构图和 Biome 图分开画，互不牵制：结构图边界是硬的（就是崖），Biome 图边界照旧渐变。【已定】
- 检查只报错，不自动修改 layout 区域；问题由负责人改 layout 或手修体素。【已定】
- 生成后可以手改体素（GDD 半手工流程【已定】）。手改地形会清空该 chunk 的环境层和植物层；编辑工具在手改后重新跑连通检查并提示。

## 5. Layout 数据

### 5.1 结构图与区域

结构图是一张粗网格，1 格 = 8m（16×16 chunk 的世界为 128×128 格），每格记一个区域 ID。【暂定】

每个区域的字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 区域 ID |
| `parent` | 父区域，可空；支持嵌套（如大台地里套一个盆地） |
| `kind` | 区域类型，见 5.2 |
| `level` | 基准层级；有父区域时相对父区域计算 |
| `interior` | 内部地形参数（起伏幅度、矮台地覆盖率等），默认取 Biome 参数 |

- 两个相邻区域之间的崖高 = 两边 `level` 之差；崖的位置就是区域边界。【已定】
- 开放区不制造崖：两个开放区相邻时层级差靠平滑过渡消化，不成崖；崖只出现在台地、盆地、峡谷、高原这些结构区域的边界上。【已定】
- 相邻 chunk 不等于可以通行；区域之间只能经出入口通过。【已定】

### 5.2 区域类型

| 类型 | 典型层级 | 边界 | 内部 | 状态 |
| --- | --- | --- | --- | --- |
| 开放区（森林、沼泽、人类区等） | 0 左右 | 自己的边界不成崖：和其他开放区平滑过渡；挨着台地、盆地、峡谷、高原时，崖属于对方的边界 | 自然起伏 + 1–2 层矮台地 + 少量 3–4 层台地 | 【已定】 |
| 台地区 | 周围 +3–4 | 一圈崖，只在出入口处有坡道 | 平整或轻微起伏 | 【已定】 |
| 盆地 | 周围 −2 及以下 | 一圈崖；跳进去，原路出不来 | 平整或轻微起伏；另有出口 | 【已定】 |
| 峡谷 | 两侧高、谷底低，常切在高处 | 两侧长崖 | 沿狭长通道移动；谷底要有自己的出入口 | 【已定】 |
| 高原 | 每级 +3–4，叠多级到 16–24m | 外缘可以 7 层以上直接落到森林 | 多级台地 | 【已定】 |
| 随机区域组 | 跟随周围 | 接缝沿用邻居边缘高度（GDD） | 运行时生成 | 【已定】（GDD） |

- 沼泽：从沼泽底面算起，自身起伏加叠起来的矮台地，总高度不超过 3m。【已定】
- 开放区里允许 2 层矮台地，它会形成短的单行边，绕路要短。【已定】
- 盆地底部最低 −8（地下上限）；底部以下剩余的厚度用来放洞穴、矿脉。

### 5.3 出入口

出入口标在区域边界上，生成器只在这些位置开口，其余边界保持崖。【已定】

| 类型 | 方向 | 说明 |
| --- | --- | --- |
| 坡道 | 双向 | 2–3 格宽（沿用现有生成器） |
| 台阶 | 双向 | 每级 1 层 |
| 跳下 | 单向 | 高差决定代价（见第 3 节） |
| 桥 | 双向，不连通桥下 | 见 5.6 |
| 隧道 / 拱 | 双向，不连通上方 | 见 5.6 |

- layout 里的台地：出入口由布局决定，跟着道路走。【已定】
- 自然地形里的普通台地（区域内部噪声生成的）：生成器默认每块 1–2 个坡道，大块的多一些。【已定】

### 5.4 关键地点与模板

关键地点包括城市、村庄、住所、长线副本入口、野外建筑、自然奇观。地点可以小于一个 chunk，也可以跨越多个 chunk。【已定】（codexsug）

地点在 layout 里写“模板 + 位置 + 朝向”；生成器按模板盖一个**地形印章**，作为硬约束，再在周围生成自然地形。

模板字段：

| 字段 | 含义 |
| --- | --- |
| `footprint` | 占地，矩形或多边形，单位 m |
| `terrain` | 占地内的地形要求（平整、相对层级、要求一面崖、要求一段落差 + 水池等） |
| `buffer` | 占地外不放台地和杂物的宽度 |
| `connectors` | 接道路或小径的位置 |
| `rotations` | 允许的朝向 |
| `fixed` | 所在 chunk 是否固定（关键地点一律为是） |
| `prefab` | 占位 ID，以后接 Unity 预制件 |

占位尺寸【暂定】，负责人可随时改：

| 地点 | 占地 | 地形要求 | 备注 |
| --- | --- | --- | --- |
| 住所 | 1 个 chunk（64×64） | 大部分平整 | GDD：只能在自家 chunk 种植 |
| 小村庄 | 约 1 个 chunk | 平整为主，可有 1 层起伏 | |
| 港口城市 | 2×2 到 3×3 个 chunk | 临海，0 层附近 | 技术验证不放 |
| 废弃小屋 | 12×12m | 平整 | buffer 4m，连接点 1 个 |
| 废弃驿站 | 24×24m | 平整，在道路边 | 连接点 2 个 |
| 遗迹 | 16–32m | 可以带台阶 | |
| 洞穴入口 | 8×8m | 背后有至少 3 层高的崖 | |
| 瀑布湖 | 约 32×48m | 4–6 层落差 + 水池 | |
| 长线副本入口 | 16×16m | 按副本定（深渊：高低地形交界） | |

### 5.5 道路

- 道路是折线，每个点带高度；跟着已定的高差、出入口和单行通道走。【已定】
- 包含连接聚落的常规道路，以及通往野外地点的小径、山路；chunk 布局阶段不分主干道与支路。【已定】（codexsug）
- 两条道路在平面上重叠处，layout 里明确标为**平交**（路口，互通）或**立交**（上下不互通）；生成器不猜。【已定】
- 马车网络是道路网的子集，与徒步网络不必相同；马车的通行规则见第 13 节。

### 5.6 桥、拱、隧道

立交的上层走桥面或台地，下层从桥下或隧道穿过，上下不互通。【已定】

| 项目 | 设定 | 状态 |
| --- | --- | --- |
| 下层净空 | 至少 3 层（人和马车都能过） | 【暂定】 |
| 桥面厚度 | 1 层 | 【暂定】 |
| 上层路面 | 至少比下层高 4 层 | 【暂定】 |
| 桥的 `railing` 字段 | 默认 `true`；只给检查用，不生成模型 | 【已定】 |

- 护栏模型由负责人在 Unity 里手动加。预览图标出 `railing = true` 的桥，提醒补护栏。
- `railing = false` 的桥被检查视为“桥面 → 桥下”的单行跳下边，可以用作付出代价的近路。
- 天然拱和隧道是挖在台地里的悬空体素，位于 0 层以上，不受地下限制。
- 错切视角下，桥面会盖住桥下一段路面，靠遮挡虚化（GDD【已定】）处理；可读性在 Unity 原型中验证。

### 5.7 约束

layout 可以写额外约束，由检查验证，不满足就报错：

- 步行距离下限：如“A 到 B 的步行距离不少于 300m”，用来验证“直线近但路程远”。【已定】
- 预览工具输出关键地点两两之间的直线距离、步行距离和绕路倍数。

## 6. 区域内部生成

区域内部交给噪声和 Biome 参数，但不能改变区域之间的连通关系。【已定】

- 内部台地、碎石、杂物不能碰到区域边界和出入口，也不能在区域内部围成闭合的墙。
- 开放区的 3–4 层台地是被可走地面围着的岛，不切断区域内部的通行。
- 微起伏、矮台地、池塘、碎石的参数沿用 GDD 6.3 各 Biome 起伏参数表，并按第 3、5.2 节的上限钳制。
- 7 层以上的崖只出现在 layout 指定的位置（主要是高原边缘），生成器不刻意造深峡谷。

## 7. 水

- 海水只填和海连通、且低于 0 层的区域。【已定】
- 内陆的湖、池塘、河由水系生成（GDD 第 6 节规则），与高度是否低于 0 无关。【已定】
- 其余低于 0 层的地方是干的盆地或谷底。【已定】
- 海底最深约 −4；再往外是“深水，不可通过”，不建模。【暂定】

## 8. 固定 chunk 与随机区域

**固定 chunk**【已定】

- 凡是碰到关键地点、道路、区域边界、出入口、桥和隧道的 chunk，一律固定。
- 固定 chunk 及其关键地理关系不因随机区域刷新而改变。

**随机区域**【已定】

- 随机区域组只用剩下的完整 chunk（与 GDD“随机区域由策划指定的 chunk 组成”一致）。
- 随机区域不能是固定区域之间的必经之路：固定世界在不经过任何随机区域的情况下自己连通。随机区域是挂在固定世界上的“口袋”。
- 刷新规则沿用 GDD：以组为单位重新生成，睡眠触发，开放 1–3 个出入口，接缝与固定 chunk 连续。
- 组的大小、形状不一；允许局部密集、局部稀疏；组与组之间保持间隔；可以靠近聚落、长线副本或偏僻野外。【已定】（codexsug）
- 在满足固定世界结构的前提下，尽量提高随机 chunk 的占比；目标占比【待讨论】。

## 9. 检查

生成后自动跑，只报错，不自动修改 layout 区域。【已定】

1. **有向连通**：从住所出发能到达所有固定区域；从任何能到达的地方都能回到住所。单行路段要么通往出口，要么有别的办法出去（GDD）。随机区域不参与这项检查。
2. **出入口一致**：实际地形里区域之间的每条通路都对应 layout 里的一个出入口；没有多出来的通路。
3. **步行距离约束**：见 5.7。
4. **高度范围**：地面在 −8 到 +56 之内；超过 32m 的格子给出提示。
5. **桥**：列出 `railing = true` 的桥。

连通与距离都按**三维可站立表面**计算：桥面和桥下、隧道上方和隧道内是不同的节点。

## 10. 技术实现要点

- 高度图负责自然地面；桥、拱、隧道作为三维结构印章叠加；可站立表面图由二者共同生成。
- 生成核心仍是纯 C#（`noEngineReferences`），不用 `System.Random`、`Math.Pow/Sin/Exp` 等，保证 .NET 与 Unity 结果逐格一致。
- layout 数据位置：`Assets/Wort/Data/Layout/`，一张区域网格图 + 一份 JSON（区域、出入口、地点、道路、约束）；地点模板单独成 JSON。【暂定】
- 云端预览渲染：结构图、Biome 图、高度图、出入口、道路、桥（上下层分开画），以及检查结果。
- 改了生成算法，checksum 会变：同时更新 `Assets/Wort/Tests/EditMode/GenerationTests.cs` 的期望值和 `Docs/LocalSetup.md` 的数字。

## 11. 技术验证：8×8 测试 layout

在现有 8×8 实验区（512m × 512m）手写一份小 layout，每种机制各放一个：

- 住所（1 个 chunk）和一个小村庄，之间一条道路。
- 一座废弃小屋，用小径连接。
- 一块 +4 台地区，只有 1 个坡道口；崖面上有一个洞穴入口。
- 一个 −2 盆地：跳进去，从另一侧出来。
- 北边一段高原落差（7 层以上），下面接森林。
- 一组“直线约 100m、被峡谷或台地隔开、步行距离 ≥ 300m”的地点，验证步行距离检查。
- 一处立交：一座桥、一条隧道。
- 其余为开放森林和一小块沼泽。

这份 layout 验证完即弃，不沿用到 16×16。
