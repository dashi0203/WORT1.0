玩法只认 1m 体素格；画面上的地形是由体素推导出来的美术网格。本文规定这一步“体素转外观”怎么做、美术交付什么。标记沿用主 GDD：【已定】【暂定】【待讨论】。

## 1. 原则

数据层和外观层分开：碰撞、跳跃、连通、生成校验只看 1m 体素格；美术网格只管好看，不加碰撞。【已定】负责人 2026-11-11

- 画面上的地面不超出碰撞格（倒角只往里收），不会出现“看着能站、实际掉下去”；侧面在人脚下方最多往外鼓约 0.45m（含崖脚外扩），贴着崖脚走时会略穿进石头。【暂定】
- 外观不改变生成结果：同一种子的 checksum 不变，外观换版不影响玩法。【已定】
- 整体不用平滑曲面，一律是硬边低模多边形（主 GDD：地表不用平滑网格【已定】）。

镜头决定可见面：正交俯视加纵向错切，画面里只看得见顶面和朝南的竖面。朝北、朝东、朝西的竖面看不见。【已定】

- 崖的层次、岩层、崖脚细节，只在朝南的面上花功夫。
- 朝北的崖只能靠顶面边缘让人看出来，所以每条崖的顶沿都必须有“轮廓被打破 + 亮线加暗线”（第 3 节）。【已定】

## 2. 做法：方案 B（立方体 + 倒角 + 外鼓）

每格仍是立方体，外观网格全部由程序从体素生成（`CliffMesher`），形状参考 topdowntemp 的悬崖件，但不做件。【暂定】负责人 2026-11-11：先试 B。早先的“截面扫掠”和顶点变形原型已废弃。

| 部位 | 做法 | 数值 |
| --- | --- | --- |
| 顶面 | 平的；不靠崖边的平地按同高矩形合并 | — |
| 外倒角 | 露出的顶边、外角竖边往里收 | 0.1m |
| 内倒角 | 凹角的竖边和顶边；凹角处两条顶边的倒角斜接（角上那格顶面切掉一个倒角见方，两块斜面沿对角线接上），不补小直角 / 小三角（负责人 2026-11-12） | 0.04m |
| 外角补地面 | 外角倒角削掉的小三角下面补 1 个三角形 | — |
| 侧面外鼓 | 同一面墙两端情况相同的连续几层合成一段；两层 Voronoi：大块 2.2m 一格定整体凸起、小块 0.65m 一格加细节 | 最多约 0.26m |
| 崖脚外扩 | 贴地处最大，0.7m 以上为 0；朝南的面不外扩（负责人 2026-11-12：外扩会让正面显得长） | 0.18m |
| 斜坡（坡道） | 和崖顶同一套做法：坡面露出的侧边收进外倒角并倒一条斜着的角，一圈岩石边随露出高度变宽（坡底与平地同高处没有）；侧面是一整块鼓包岩石墙（崖脚 → 斜边）；北面（背面）鼓包和崖脚外扩加大；坡顶接台面、坡底接平地处不画墙、不倒角，路面连续。负责人 2026-11-12 | 北面鼓包 ×3（离顶边 1.2m 内减到 0）、崖脚外扩 ×3.5（不超过墙高一半）；朝南鼓包 ×0.5；坡道上岩石边 0.12–0.3m、路面边距 0.15–0.35m |
| 侧面细分 | 朝南（镜头看得见）每 0.25m 一行；东西每 0.5m 一行、列减半；北面不细分不鼓 | — |
| 碰撞 | 1m 格同高矩形合并成 BoxCollider + 斜坡小网格（`ColliderBoxes`） | 每 chunk 约 220 个盒 |

以上数值全部【暂定】，等 Unity 里看过再调。

方案 A（美术做件）保留为以后的选项：允许旋转时 5 种形状 + 1 个内角补块，约 6–10 块；平地不用件；大量同网格物体用 Unity 6 的 GPU Resident Drawer。【待讨论】

## 2.1 程序化崖壁（负责人 2026-11-13，测试地已接入）

方案 B 的新做法：顶面和正面都是平面，体积交给从真实几何烘焙出的无缝法线；几何只做轮廓。测试地上它比模块化瓦片更省（见第 5 节），先在测试地验证，再推广到正式世界。【暂定】

| 部分 | 做法 |
| --- | --- |
| 顶面 | 每格平的 1m 方块，不变形；四周同高的格按同高、同套件合并成大矩形 |
| 正面（朝南） | 平面，贴图按世界坐标连续；同高、同崖脚、同套件的一排连成一段 |
| 侧面鼓起 | 只鼓“看得见的体素层”：这一列最上面那块（顶层）的东西侧面，和南面露出的那块（前排）的东西侧面；崖顶处也鼓出约 3–14cm（顶面侧边接一条同高窄条），往下更鼓（最多约 0.3m），崖脚处收为 0；有正面的格在南端、被斜对角封住的一端收为 0，转角落回格线；坡道东西两侧同样鼓出 |
| 看不见的面 | 北、东、西竖面各一块平面，只投影不渲染，保证影子完整 |
| 顶面两层 | 顶岩铺满（周期 2.7m），泥土离露边往里收 15–35cm（不规则）；人类区用单独的顶岩贴图，沼泽、森林的顶岩就是泥土 |
| 平滑法线 | 顶沿、竖直转角在折线两侧各转 45°（崖脚不转，改成墙根和地面 0.35m 内同一条压暗曲线，墙根贴地处法线与地面一致），两边同一个宽度函数（18–32cm）；石头法线细节跟着表面一起转，不淡出 |
| 融合 | 墙顶 35cm 融合顶岩（展开取样，石块从顶面绕到墙上），崖脚 35cm 融合泥土（法线也跟着换） |
| 轮廓与影子 | 顶面北边往北伸出一条同高窄条（3–14cm，按噪声），和侧边窄条用四分之一椭圆补角；投影用标准做法（迎光面投影），影子边缘不再刻意咬碎 |
| 着色 | 暗部提亮 0.08；崖壁本身提亮 12%、加饱和 12%（不作用在融合进来的泥土、顶岩上） |

画面上的地面会略超出碰撞格（北边裁剪只往里收；侧面鼓起在人脚下方），玩法和 checksum 不变。实现：`ProcCliffMesher`（生成核心）+ `Wort/ProcCliff`（着色器），`TerrainLab` 里和瓦片可来回切换。

## 3. 贴图融合

顶面是泥土，崖边一圈和侧面是岩石，两张贴图按每个顶点的融合权重渐变。【暂定】负责人 2026-11-11

- 贴图：泥土、岩石各一张，至少 128×128，1 张 = 1m，A 通道 = 高度。现阶段是程序生成的占位贴图（`TerrainTextures`），预览和 Unity 共用。
- 权重：离崖边 ≤ 0.12m 全岩石，≥ 0.5m 全泥土，分界加噪声；侧面和倒角全岩石。
- 交界：权重加两张贴图的高度差，高的先露出来，石头从泥土里透出，不是一条直的渐变。
- 路面：第三张贴图（踩实的土，A 通道 = 高度），每个顶点一个路面权重（`RoadSurface`），按与泥土的高度差融合，先盖在泥土上、岩石再盖在最上面；离崖边 / 崖脚 0.35m 内没有路面，0.6m 外完整。【暂定】负责人 2026-11-12
- 投影：顶面用世界 xz，侧面用沿墙坐标和高度；再叠一组 2.3m 一张的坐标取平均，减轻平铺重复。
- Unity：着色器 `Wort/TerrainBlend`，公式与预览相同。
- 草地毯和立起来的草片以后由植被层铺在泥土顶面上。【暂定】
- 不同 Biome 的风格（山体、荒原、沼泽）= 换一对贴图和参数；各风格具体怎么分。【待讨论】

## 4. 美术交付规格

方案 B 下美术只需要提供贴图；形状全部由程序生成。【暂定】

| 交付物 | 数量 | 规格 |
| --- | --- | --- |
| 泥土贴图 | 每种风格 1 张 | ≥ 128×128，可平铺，1 张 = 1m；A 通道存高度（小石子高） |
| 岩石贴图 | 每种风格 1 张 | 同上；A 通道存高度（裂缝低） |
| 草地毯 / 草片 | 另行定义 | 植被层，不在本文范围 |

## 5. 性能、验证与待讨论

外观网格在生成时合并成每个 chunk 一个网格，运行时没有额外开销，只在随机 chunk 刷新时重建。【已定】

| 项目 | 实测（云端 .NET，种子 3，5×5） |
| --- | --- |
| 三角形 | 全世界约 138 万，每 chunk 约 5.5 万 |
| 外观网格 | 每 chunk 约 7.5 ms |
| 碰撞盒合并 | 每 chunk 约 0.2 ms |
| 随机区域刷新 | 40–180 ms（含校验失败重试） |

Unity 验证：选中 Terrain Lab，`Generator` 设为 `Terrace5x5`、种子 3，勾上 `Cliff Dressing` 和 `Random Chunk`，点“生成”；点“重新生成随机 chunk”只重建右上角随机 chunk 及周围一圈，Console 打印各步耗时。

程序化崖壁与模块化瓦片对比（负责人 2026-11-13，同一块测试地，Unity Stats）：

| 路线 | 三角形 | 顶点 | Batches | SetPass | 帧时间 | 生成耗时 |
| --- | --- | --- | --- | --- | --- | --- |
| 模块化瓦片 | 417.4k | 1.2M | 92 | 60 | 2.0 ms | 97 ms |
| 程序化崖壁 | 28.3k | 81k | 65 | 30 | 1.7 ms | 29 ms |

贴图分辨率：原图保留 512（1 张 = 1m），以后统一在导入设置里压到 256（显存约省 4 倍，俯视镜头下画面基本不变）。【暂定】

待讨论：

- 侧面外鼓和崖脚外扩与碰撞的偏差（最多约 0.45m）是否可接受。【待讨论】
- 网格生成换到多线程（各 chunk 互不影响）；随机区域生成提前判失败、减少重试。【待讨论】
- 美术风格走 PSX 低模还是参考图那种手绘卡通质感（主 GDD 第 3 节【暂定】）。【待讨论】
